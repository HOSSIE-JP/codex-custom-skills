# AI Character Reference Reconstructor

参照画像に写る同一キャラクターを分析し、AIで再利用しやすい一貫したキャラクター正本へ再構築する。

## 絶対的な出力契約

次の成果物を、**1枚へ統合せず、必ず独立した画像ファイル**として生成する。

1. `character_reference_01_fullbody_four_directions.png`
   - FRONT / LEFT / BACK / RIGHT
2. `character_reference_02_head_six_directions.png`
   - FRONT / 3/4 LEFT / 3/4 RIGHT / LEFT / RIGHT / BACK
3. `character_reference_03_six_expressions.png`
   - SOFT SMILE / JOY / ANGER / SADNESS / SURPRISE / FEAR
4. `character_reference_04_key_parts_details.png`
   - 必要な場合のみ生成する

画像内へ英語タグ辞書や統合タグ列を埋め込まない。画像完成後、次の2項目をコピー可能なテキストとして出力する。

1. `English Prompt Tag Dictionary`
2. `Integrated Tag String`

一つの巨大な総合シート、四つのシートを並べたコラージュ、タグ欄を画像下部へ足したレイアウトは禁止する。

## 入力の前提

- 参照画像は1枚以上を想定する。
- ユーザーが各画像の用途を指定した場合、その指定を最優先する。
- キャラクターが複数写る場合は、対象が明らかならその人物だけを採用する。対象が特定できない場合のみ、短く確認する。
- 参照画像がバストアップでも全身シートを省略しない。
- 参照画像で見えない箇所は、確認できる造形言語、装飾密度、素材、配色、モチーフ、時代感、シルエットから保守的に補完する。
- 装飾性の高いキャラクターを勝手に簡素化しない。簡素なキャラクターへ根拠のない装飾を追加しない。
- 補完した構造は第1画像で正本化し、以後の画像とタグでも変更しない。

## 正本の優先順位

矛盾する情報がある場合は、次の順で採用する。

1. ユーザーの明示指定
2. 専用の設定画、三面図、衣装設定、キャラクターシート
3. 最も鮮明で遮蔽の少ない全身画像
4. 最も鮮明な顔・頭部画像
5. その他の補助画像
6. 視覚的に整合する保守的な推論

画像を無作為に平均化しない。別衣装、別時期、変身前後が混在する場合は、ユーザー指定または最も一貫した主デザインを正本とする。

## 生成前の内部分析

ユーザーへ長い分析文を見せる必要はないが、生成前に内部で次を固定する。

- 顔の輪郭、目、眉、鼻、口、肌色
- 髪色、髪の長さ、前髪、横髪、後ろ髪、毛先、分け目
- 頭身、肩幅、体格、脚の比率
- 衣装の上半身、下半身、袖、襟、手袋、靴
- 主配色と差し色
- アクセサリー、装備、携行品
- 左右非対称部分と、キャラクター自身から見た左右
- 背面で初めて分かる構造
- 推論で補完する部分
- 第4画像が必要かどうか

左右は常に **character-left / character-right** を基準に管理する。単純な左右反転で非対称パーツを入れ替えない。

## 生成順序と一貫性

必ず次の順序で作る。

1. 第1画像を生成し、全身・衣装・背面・左右非対称の正本とする。
2. 第2画像を、元参照画像と第1画像の正本を参照して生成する。
3. 第3画像を、第2画像のFRONT無表情を顔の正本、第1画像を衣装の正本として生成する。
4. 第4画像が必要なら、元参照画像と第1〜第3画像を参照して生成する。
5. 最終的に確定した正本から英語タグ辞書と統合タグ列を作る。

各画像を独立生成しても、顔、髪、衣装、色、装飾、左右差を変えない。後続画像で勝手にデザインを再解釈しない。

## 第1画像：全身四方向ビューシート

詳細仕様は `references/sheet-specifications.md` を読む。

必須条件:

- FRONT / LEFT / BACK / RIGHT の4体を横並びまたは均等な4列で配置する。
- 全身を頭頂から靴底まで欠けなく表示する。
- すべて同じ縮尺、頭身、接地線、立ち位置、直立姿勢にする。
- 腕は身体から少し離し、脚と腕を交差させない。
- 動的ポーズ、パースの強いポーズ、腰を大きくひねったポーズは禁止する。
- 正投影に近い設定画表現にし、広角歪みを避ける。
- 表情は無表情またはごく弱いニュートラルに統一する。
- 背面の髪、リボン、留め具、衣装の接続を合理的に確定する。
- FRONTとBACKを単純反転して作らない。
- LEFTとRIGHTで左右非対称を正しく保つ。
- 白または非常に薄い無彩色の背景を使う。
- 見出しと方向ラベル以外の説明文、タグ、長文注釈を入れない。

## 第2画像：頭部六方向ビューシート

必須条件:

- FRONT / 3/4 LEFT / 3/4 RIGHT / LEFT / RIGHT / BACK の6枠。
- 頭部から肩上部までを同じ大きさ、同じカメラ距離、同じ高さで表示する。
- 全方向を無表情に統一する。
- 第2画像のFRONT無表情を顔の正式な基準にする。
- 鼻、顎、後頭部、耳、前髪と後ろ髪の接続、頭部アクセサリーの奥行きを示す。
- 斜め角度で別人化させない。
- LEFTとRIGHTを単純反転しない。
- 参照にない髪飾りやピアスを増やさない。
- 表情、口の開閉、視線、肩の向き以外の余計な変化を入れない。

## 第3画像：厳選六表情シート

必須条件:

- SOFT SMILE / JOY / ANGER / SADNESS / SURPRISE / FEAR の6枠。
- 正面の頭部〜肩上部で、同一の表示範囲、カメラ、頭の角度、衣装を使う。
- 顔立ち、髪、アクセサリーは第2画像のFRONT基準から変えない。
- 表情だけを変える。
- SOFT SMILE: 口角を軽く上げた穏やかな微笑み。誇張しない。
- JOY: 明確な喜び。目や頬にも幸福感を出す。
- ANGER: 眉を下げ、視線を強め、口元に緊張を作る。
- SADNESS: 眉尻と口角を下げ、静かな悲しさを作る。
- SURPRISE: 眉を上げ、目と口を自然に開く。恐怖の緊張は入れない。
- FEAR: 眉を中央へ寄せ、目元と口元を緊張させる。単なる驚きにしない。
- 泣き顔へ固定しない。涙はキャラクター表現上必要な場合のみ控えめに使う。

## 第4画像：固有パーツ詳細シート

次のいずれかが存在し、通常の3枚だけでは構造を再現しにくい場合のみ生成する。

- 複雑な髪飾り、冠、帽子
- 特殊な耳、角、翼、尻尾
- 武器、杖、鞄、携行品
- 衣装固有の留め具、紋章、模様、編み上げ
- 表裏で構造が異なる大型リボンや装備
- 機械関節、変形・可動構造
- 小さいが重要な左右非対称パーツ
- 手袋、靴、アクセサリーなど、他シートでは潰れる重要部品

生成する場合:

- 各パーツを大きく、遮蔽なく、正面・側面・背面など必要最小限の角度で示す。
- 全身や表情を再掲して枠を埋めない。
- 色見本を入れてもよいが、英語タグ辞書や統合タグ列は入れない。
- パーツ名称の短い英語ラベルだけを使用する。

通常的な人型で第1〜第3画像から十分に再構築できる場合、第4画像を作らない。枠数を満たすためだけに生成しない。

## 画像生成時の共通禁止事項

- すべてを1枚へ詰め込む
- 画像ごとに別衣装、別髪型、別顔へ変える
- 立ち絵ごとにポーズや縮尺を変える
- 手足、髪、帽子、靴、リボン端を切る
- LEFTとRIGHTを単純反転する
- 非対称パーツの向きを入れ替える
- 不要な小物、武器、装飾、ロゴ、透かしを追加する
- 背景シーン、床のパース、ドラマチックな照明を入れる
- 参照画像の画風を無断で実写化、3D化、別アニメ調へ変える
- タグ辞書や統合タグ列を画像へ描く
- 読めない大量の文字を画像内へ生成する

## 英語タグ辞書

画像生成後、`references/tag-taxonomy.md` に従って英語で整理する。

- Markdown見出しとコードブロックを使い、コピー可能にする。
- 観察または正本化した情報だけを書く。
- 重複語、同義語の過剰列挙、価値の低い美辞麗句を避ける。
- キャラクター名はユーザーが提示した場合のみ含める。
- 左右非対称は `character's left` / `character's right` を明記する。
- 画風、線、陰影、色設計も含める。
- 第4画像を作った場合は、その固有パーツを必ず含める。

## 統合タグ列

- 1本の英語カンマ区切り文字列としてコードブロックで出力する。
- 原則として自然言語タグを使い、snake_caseへ変換しない。ユーザーがStable Diffusion形式などを指定した場合のみ形式を合わせる。
- 顔と髪、シルエット、衣装、配色、アクセサリー、非対称、画風の順に、識別力の高い要素を優先する。
- 六表情すべてを列挙しない。通常状態の外見タグにする。
- 同じ意味のタグを繰り返さない。
- 生成モデルへ誤解を与える曖昧な左右表現を避ける。

## 最終応答の形式

画像ツールが利用可能な場合は、各画像を独立ファイルとして生成・提示する。テキスト部分は次の順にする。

````markdown
## 1. English Prompt Tag Dictionary

```text
...
```

## 2. Integrated Tag String

```text
...
```
````

第4画像を作らなかった場合は、短く「第4画像は不要と判断」とだけ記す。長い制作解説は付けない。

画像生成ツールが利用できない環境では、生成済みだと装わない。代わりに、各画像を別々に生成できる完成プロンプトを3本または4本と、タグ辞書・統合タグ列を出力する。

## 品質確認

最終提示前に `references/quality-gate.md` のチェックを行う。重大な不一致がある画像は、そのまま採用せず再生成する。
