# 「いしのうらにいる！？」PCE VN話数制作

このスキルは、女子部活日常コメディ「いしのうらにいる！？」の新しい話を、正本資料に従って設計・執筆・検査するための専用ワークフローである。

## 最優先ルール

1. プロジェクト内の正本を探して先に読む。
   - `docs/series-bible.md` または `series-bible.md`
   - `docs/asset-catalog.md` または `asset-catalog.md`
   - `docs/chatgpt-authoring-workflow.md` または `chatgpt-authoring-workflow.md`
   - スクリプト工程では `assets/pce-vn-scenes.json`
   - スクリプト工程では `assets/pce-assets.json`
   - ユーザーが承認したシナリオ設計
2. 同名のプロジェクト資料がある場合、`references/` の同梱資料よりプロジェクト側を優先する。同梱資料は基準スナップショットである。ただし、この `SKILL.md` の工程分離と禁止事項は常に守る。
3. 資料にないキャラクター設定、話者名、asset ID、command、エンジン仕様を作らない。
4. 事実とキャラクターの偏見を分離する。時点で変わり得る製品・価格・販売数・契約条件は、ユーザー提供資料または確認済み一次情報なしに断定しない。
5. 部長だけを正解にせず、レンを悪役にせず、チカを専門家にしない。
6. 画像やJSONが不足している場合、完成したと装わない。不足物と次工程を明示する。
7. **シナリオ設計の時点で自然な会話の流れを設計する。** テーマを説明文としてキャラクターに読ませず、直前の出来事への反応、質問、言い訳、具体的な結果、本人の実感で浮かび上がらせる。
8. **このスキルはイベントスチル画像を生成しない。** ChatGPT Image、`image_gen`、その他の画像生成機能を呼び出さず、人間が別途ChatGPT Imageへ貼り付けられる完成プロンプトを作るところで止める。
9. 画像プロンプトだけを作った状態を「画像生成済み」と報告しない。状態は `PROMPT_READY / IMAGE_PENDING_HUMAN` と明示する。
10. 人間が生成した画像を受け取るまでは、登録済み画像を前提としたstrictな完成JSONを作らない。ユーザーが明示的に仮参照を求めた場合だけ、未登録であることを明示してプレースホルダ統合案を出せる。
11. 画像ファイルの生成、切り貼り、合成、クロップ、リサイズ、減色、パレット化、コンタクトシート作成、画像検査にはPython、Pillow、OpenCV、matplotlib、NumPy、SVG、HTML canvas、プログラム描画を使わない。PCE変換は人間がPCE Game EditorのImage画面で行う。
12. JSON parse、台詞文字数、scene遷移、分岐到達性、asset IDなど、画像へ触れない検査には既存validatorを使ってよい。
13. イベントスチルのキャラクター固定には、`references/image-generation-policy.md` で指定する今回の3.2頭身・4頭身設定画だけを使う。3.2頭身を標準とし、コミカル度が低い場面だけ4頭身を使う。同一スチル内で頭身を混在させず、5.5頭身版や旧 `ref_*.png` へフォールバックしない。

必要に応じて次を読む。

- キャラクター・シリーズ判断: `references/series-bible.md`
- 自然な会話設計の詳細: `references/natural-dialogue-guidelines.md`
- asset ID・画像・音声判断: `references/asset-catalog.md`
- JSON仕様・工程・受け入れ条件: `references/chatgpt-authoring-workflow.md`
- 画像プロンプト引き渡しの最優先規則: `references/image-generation-policy.md`
- 短い実務チェック: `references/production-checklist.md`
- scene会話設計カード: `templates/scene-dialogue-card.md`
- 画像プロンプト引き渡し票: `templates/event-still-prompt-handoff.md`

## 依頼を工程へ振り分ける

ユーザーの依頼を次のいずれかへ分類し、その工程だけを実行する。複数工程を頼まれた場合は順番に進める。

### A. シナリオ設計

台詞全文やJSONをまだ作らない。設計は、出来事の順番だけでなく「なぜ今その人物がそれを言うのか」まで決める。

必須出力:

1. 作品概要と仮タイトル
2. 確認済み事実と各キャラクターの偏見
3. scene候補一覧と想定message数
4. 部長・チカ・レンの攻守表
5. sceneごとの会話設計カード
6. 分岐1の2択、短い差分、共通合流先
7. 分岐2の2択、短い差分、共通合流先
8. 既存asset利用表
9. イベントスチル計画とプロンプト設計メモ
10. イベントスチル以外の不足asset
11. 合計想定message数
12. 自然な会話・シリーズ設定セルフチェック

各sceneの会話設計カードに必ず含めるもの:

- 直前に起きた具体的な出来事
- scene開始時の各人物の感情
- 各人物がその場で得たいもの
- 最初の発話を生むきっかけ
- 反応→主張→質問／反論→具体例→変化／オチの会話運動
- 言葉ではなく画面で見せる行動や物
- テーマの下地。キャラクターにそのまま言わせない抽象的な意味
- 会話終了時の感情と次sceneへのつながり
- 不自然になりやすい台詞の型

基準:

- 1話15〜20分、全scene合計220〜280 message
- 2択を2回
- 選択肢はチカの反応または行動
- 各分岐は数messageから十数messageで合流
- 現物または実際の行動による因果応報
- 最後にチカの日常的な観察
- 短いタグのオチ
- 話数固有イベントスチルは最低3枚
- 必須スチルは原則として全ルート共通経路で見られる構造
- 各スチルに、人間がChatGPT Imageへ渡すための構図・感情・参照画像メモを付ける
- すべてのsceneで、次の台詞が直前の台詞または出来事へ反応していること
- 教訓は勝者の長い説教ではなく、対象者が具体的な不利益を自分の言葉で理解する流れにする

### B. イベントスチル選定・画像生成プロンプト作成

この工程では画像を生成しない。標準の役割は次の3枚である。

- `epNN_001`: 題材・現物の提示
- `epNN_002`: レスバまたは因果応報の最高潮
- `epNN_003`: エンディングまたはタグのオチ

必要なら4枚目以降を追加し、追加理由と使用sceneを明示する。

1枚ごとに次の「画像プロンプト引き渡し票」を作る。

1. asset ID案
2. 使用scene
3. 画像にする一瞬と物語上の目的
4. コミカル度、選択頭身、選択理由
5. 添付すべき参照画像の一覧
6. 人物配置、カメラ距離、視線、ポーズ、表情、小物、背景
7. 28:17へ安全にクロップできる構図上の安全領域
8. ChatGPT Imageへそのまま貼れる自己完結した完成プロンプト
9. 完成プロンプト内に統合した禁止事項
10. 生成後に人間が確認する受け入れ項目
11. 問題が出た場合に使う修正プロンプトの雛形
12. 状態 `PROMPT_READY / IMAGE_PENDING_HUMAN`

#### 絶対禁止

- ChatGPT Imageや`image_gen`をこのスキルから実行する
- 画像生成済み、224×136済み、16色済み、登録済みと偽る
- Web画像、旧スチル、立ち絵の切り貼りを新規スチルとして扱う
- Pythonその他のプログラムで画像を作成・修正・検査する

#### 人間への引き渡し

人間は、指定された参照画像を添付し、完成プロンプトを別途ChatGPT Imageで実行する。生成後、PCE Game Editorで224×136化、減色、background asset登録を行い、更新後の`pce-assets.json`を次工程へ渡す。

### C. 台詞全文と `pce-vn-scenes.json` 生成

承認済み設計と、登録済みイベントスチルを含む現行JSONを基に全文を作る。

#### 台詞の内部作業順

1. まず改行制約を外した自然な口語として発話を書く。
2. 直前の発話へ反応しているか、質問と答えが対応しているかを確認する。
3. 話者を入れ替えても成立する汎用台詞を、各人物固有の言い方へ直す。
4. 抽象的な教訓を、具体的な質問、行動、結果、本人の実感へ分解する。
5. 音読し、助詞の重なり、書き言葉、長い修飾、説明口調を修正する。
6. 最後に意味と息継ぎを壊さない位置でPCE表示用に分割・改行する。

構造:

- `version: 2`
- `startScene: "logo"`
- `settings`、`logo`、`title`、`eye_catch`を維持
- `title`内のゲーム開始jumpだけを新話冒頭へ変更
- 新話末尾から`eye_catch`へjump
- scene IDは`epNN_*`
- scene nameは`第NN話/...`
- 旧話数sceneを残さない

台詞:

- 1話220〜280 message
- 2択を2回、各2択
- 各分岐は短く、共通sceneへ合流
- 話者あり本文は最大3行
- ナレーションは最大4行
- 各行17文字以内
- `message.text`は96文字以内
- 句点と読点は原則使わない
- `voiceAssetId`は空文字
- 部長の`mouthSlot`は0
- チカの`mouthSlot`は1
- レンの`mouthSlot`は2
- ナレーションは`mouthSlot: null`
- 1メッセージは原則として1つの発話行為にする
- 同一話者の連続は通常2メッセージ以内。説明や感情の高まりで3つになる場合は、その直後に反応を置く

使用command:

- `background`
- `sprite`
- `spritemove`
- `message`
- `audio`
- `choice`
- `jump`
- `wait`
- `effect`

既存のシステムsceneにある`inputcheck`、`label`、`spritetext`、`comment`は保持する。新話sceneで独自の高度な制御commandを追加しない。

アセット:

- `pce-assets.json`に登録済みのIDだけを完成JSONへ使う
- イベントスチルをまだ人間が生成・登録していない段階では、strictな完成JSONを生成せず不足IDを報告する
- ユーザーが明示的にプレースホルダ統合を求めた場合だけ仮参照を許し、「人間による画像生成・登録前」と明示する
- 背景は登録済みの学校、廊下、部室、話数固有スチルだけ
- 立ち絵は登録済みの表情だけ
- 会話BGM・SEは既存PSGを優先
- ADPCMとCD-DAはHuCARDで無音になるため、新しい会話演出へ依存させない

イベントスチルを表示するsceneでは、直前の立ち絵を`visible: false`にしてからスチルをbackground表示する。次の通常会話sceneでは背景と立ち絵を明示的に復帰させる。

### D. 既存スクリプトへイベントスチルを組み込む

1. 人間が生成・登録したスチルのasset IDを確認する。
2. 物語上の瞬間とsceneを対応付ける。
3. スチル表示がscene途中になる場合はsceneを分割し、新scene先頭へ置く。
4. スチルsceneの冒頭で表示中の立ち絵を非表示にする。
5. `background`で登録済み`epNN_XXX`を`x: 2`, `y: 1`に表示する。
6. 全分岐から必須スチルへ到達できるようにする。
7. 通常背景へ戻るsceneで背景と立ち絵を復帰する。
8. 画像ファイルそのものは生成・修正・変換しない。

### E. 検査・納品

最低限、次を検査する。

- JSON parse
- `version=2`
- `startScene=logo`
- `logo`、`title`、`eye_catch`維持
- game start jumpが新話冒頭を指す
- scene ID重複なし
- jump、choice target、nextSceneIdの欠落なし
- 2択×2回
- 全分岐が合流し、エンディングへ到達
- 必須イベントスチルが全分岐から到達可能
- 各行17文字以内
- 話者あり3行以内、ナレーション4行以内
- `voiceAssetId`は空文字
- 話者と`mouthSlot`一致
- 全asset IDが登録済み
- 各sceneのbuilder上のbudgetが4096 bytes以内
- CD-ROM2／HuCARDの両方で進行できる

自然な会話について次を検査する。

- 各発話が直前の台詞または出来事へ反応している
- 質問へ答えるか、意図的に避けたことが会話上わかる
- 抽象語より先に具体的な出来事・行動がある
- テーマを一人が長く説明していない
- 勝者が教訓を授けるだけでなく、対象者自身が具体的な不利益を言葉にしている
- チカが専門知識や作者の結論を代弁していない
- レンの似非大阪弁が短く読みやすい
- 部長の正論にも偏愛や脱線が残っている
- 同じ内容の言い換えが無目的に続かない
- 感情の変化に途中の反応がある
- 音読して口に出しにくい文がない

画像工程の納品状態は分けて報告する。

- `PROMPT_READY`: プロンプト引き渡し票が完成
- `IMAGE_PENDING_HUMAN`: 人間によるChatGPT Image実行待ち
- `IMAGE_PROVIDED`: 人間が生成画像を提供
- `PCE_REGISTERED`: 人間がPCE Game Editorへ登録し、asset IDを確認
- `SCRIPT_INTEGRATED`: 登録済みassetをJSONへ組み込み、到達性を検査

## 完了条件

### シナリオ設計完了

- sceneごとの会話設計カードがある
- 自然な会話のリスクと回避策がある
- 2択、合流、因果応報、タグのオチが設計済み
- イベントスチルの役割とプロンプト設計メモがある
- 人間の承認を受けられる状態である

### 画像プロンプト工程完了

- 各スチルの画像プロンプト引き渡し票がある
- 参照画像一覧、完成プロンプト、禁止事項、安全領域、受け入れ項目が揃っている
- 状態を`PROMPT_READY / IMAGE_PENDING_HUMAN`と明示している
- 画像を生成したとは報告していない

### イベントスチル込み話数制作完了

- 人間が生成・登録した必須スチルがある
- 更新後の`pce-assets.json`にIDが存在する
- 完成JSONが登録済みスチルを参照している
- 全分岐から必須スチルとエンディングへ到達する
- JSON、文字数、自然な会話、asset、scene budgetを検査済み
